> 기준: main `f9e3baa`에서 실행(2026-10-05 KST) · UX 감사 전담. PR을 올린 main `a960af4`까지 아래 원인 파일 중 바뀐 것은 전체 주문 화면의 「환불 요청」 버튼 추가뿐이라 결과는 같다.

## 1. 요약

- **P0 없음.** 확인한 범위: 직원·요금제 직접 URL 차단(서버 403 + 안내 화면), 다른 쇼핑몰 주문·회원 상세 접근(「찾을 수 없음」으로 막힘), 로그인 next 외부 주소(`//evil`, `https://evil`, `/admin/../\evil`)는 모두 같은 사이트 안에 머묾, 로그아웃 뒤 Back으로 로그인된 화면이 보이지 않음.
- **P1 13건.** 핵심은 세 가지다.
  1. 파트너스·마스터 관리자 목록의 검색·필터·정렬이 URL에 없어 상세 → Back(브라우저·화면 버튼 모두)에서 조건과 스크롤이 초기화된다(UX-01~03). 화면 ← 버튼은 전부 부모 주소 고정 push이고, `router.back`을 쓰는 곳은 저장소에 한 곳도 없다.
  2. 미저장 변경 보호가 상품 등록·수정에 없고, 오버레이 편집기는 링크·새로고침만 막고 브라우저 Back은 못 막는다(UX-04·05).
  3. 구매자 모바일 MY 흐름이 끊긴다: 「내 정보」에 주문 내역 진입이 없고, 하위 화면은 데스크톱 MY 메뉴가 본문 위에 펼쳐지며, 로그인 뒤 Back이 로그인 화면으로 간다(UX-07~10).
- 잘 되는 것(회귀 방지용으로 남김): 파트너스·마스터 로그인은 `router.replace`라 로그인 뒤 Back이 로그인 화면으로 가지 않는다(A2·N2). 상세 화면은 부모 LNB에 `aria-current="page"`가 켜진다(상품·주문·회원·파트너스, A6c·B3·B8·N4). 파트너스 없는 상품·주문은 안내 + 「목록으로」(A12·B5). 쇼핑몰 검색 결과·정렬은 URL(`?q=`, `?sort=`)이 기준이라 상세 → Back에서 유지된다(S4·T1). 장바구니 담기 → 로그인 모달 → 로그인 뒤 원래 상품으로 돌아온다(F3·F4). 오버레이 편집기는 저장 안 한 변경이 있으면 앱 안 링크에 「닫기 / 저장하지 않고 나가기 / 저장하고 나가기」 확인 창을 띄운다(D2).

## 5. 영역별 정리

- **IA**: 상세 화면 부모 메뉴 켜짐은 실행한 곳 모두 정상. 직원 GNB에는 「홈」이 없고, 대표자 Drawer에서 홈·시작하기는 회색(미구현) — 메뉴 숨김 정책과 미구현 표시가 섞여 있다(판단 필요 J-2).
- **Mobile Navigation**: UX-09·11·17·18. 구매자 하단 탭 높이 47px로 기준 충족.
- **Search/Filter 상태 보존**: 파트너스·마스터 목록 전부 URL 미반영(UX-01), 쇼핑몰은 반영됨. 마스터 로그 추적·청구·공지는 코드상 `useSearchParams`를 쓰나 이번 실행에서 조건 반영을 확인하지 못했다(N6: 조건 바꾼 뒤 URL 그대로, 로그 행이 없어 상세 Back은 미확인).
- **Form/Unsaved**: UX-04·05. 상품 등록 성공 뒤 `router.push("/seller/products?toast=…")` — 등록 화면이 기록에 남아 Back하면 빈 등록 폼으로 돌아간다(코드 확인, 실행은 2단계 e2e에서).
- **Modal/Overlay**: 오버레이 편집기 이탈 확인 창은 3선택지로 명확. 구매자 로그인 필요 모달은 「로그인 / 둘러보기」로 다음 행동이 있다.
- **Loading/Error/Empty**: 파트너스 없는 상품·주문, 마스터 없는 파트너스·청구는 안내 + 목록으로가 있다. 404·권한 없음 화면은 UX-12·13·16. 주문 목록 검색 0건은 「조건에 맞는 주문이 없습니다 + 필터 초기화」로 데이터 0건과 구분된다.

### 9.4 정리 · 배정 제안

1. P1: 마스터 가입 신청 목록 [승인]·[반려] 직접 처리(M1·M2), 배송·회원·리뷰·환불 요청 목록의 상태 보존(위 9.3 「깨짐」). 처리 뒤 목록 유지·행만 갱신은 `docs/ADMIN_OPS_UX.md` 원칙 3.
2. P2: 마스터 문의·공지 목록 처리(M4·M5), 상품 숨김·회원 등급 행 처리(S4·S6), 일괄 승인.
3. 이미 줄어 있는 업무(M3·S1·S2·S3·S5)는 현재 유지하고, 확인 단계(원칙 4)만 점검합니다.
4. 화면별 수정은 MASTER가 소유 세션에 배정합니다. 이 문서는 구현하지 않습니다.
