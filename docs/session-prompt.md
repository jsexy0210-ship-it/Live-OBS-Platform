# 전담 세션 지시 전문

> MASTER가 전담 세션을 만들거나 일을 배정할 때 아래 블록을 지시 맨 앞에 그대로 붙이고, 그 뒤에 이번 작업의 역할·범위·소유 파일·완료 기준을 적는다.
> 규칙을 고치면 `CLAUDE.md`와 이 파일을 함께 고친다. MASTER가 교체되면 7번의 ID도 함께 고친다.

```text
[Live-OBS-Platform 전담 세션 공통 규칙]

0. 최상위 명령: 망고TCG 저장소(jsexy0210-ship-it/obs-order-queue-cafe24-webhook)는 절대 건드리지 않는다. 쓰기 작업 일체 금지, 공개 코드 읽기(참고)만 허용.
1. 시작 전에 최신 main의 CLAUDE.md, PROJECT_STATUS.md, HANDOFF.md를 읽는다. 과거 대화가 아니라 최신 main이 기준이다.
2. 호칭은 대표님, 보고는 한국어로 결론부터, 「~했습니다」 합니다체. 화면 문구는 마스터·파트너스 관리자(관리자 로그인·계정 화면 포함)는 명사형·합니다체, 구매자·공개·오버레이·구매자 메일은 토스식 해요체(2026-10-04 대표님 지시). 화면 이름 「감사 로그」는 「로그 추적」, 시간은 KST. 화면 문구의 「판매자」는 「파트너스」로 쓴다(코드·DB·내부 문서 이름은 그대로, 2026-10-04 대표님 지시). 구매자 화면에서는 그대로 「판매자」로 쓴다. 「마스터 콘솔」은 「마스터 관리자」로 쓴다(2026-10-04 대표님 지시).
3. 배정받은 소유 파일만 고친다. 범위 밖 수정이 필요하면 MASTER에 보고하고 기다린다.
4. 작업을 마치면 반드시 PR을 건다. 브랜치 커밋·보고만으로 끝내지 않는다.
   - UI 작업은 디자인 정본 `design/SCREEN_MAP.md` → 대상 FINAL 소스 → 공통 컴포넌트 소스 → `docs/IA.md` → production 순으로 확인하고, FINAL 확인 없이 UI 구현을 시작하지 않는다. DRAFT · BLOCKED 화면은 임의 구현하지 않고 MASTER에 묻는다. 스크린샷은 검수 증거일 뿐 정본이 아니다. 디자인 전담은 캔버스를 고칠 때마다 `design/project` 동기화 PR을 낸다(커밋 `design(project): …`). (2026-10-05 대표님 지시) 캔버스를 저장하면 바로 동기화 PR을 올리고 검수 전담은 먼저 병합한다. UI 작업 전 최신 main의 `design/` 버전을 확인한다(2026-10-06 대표님 지시 「항시 모든 세션은 디자인 정본 최신 버전」).
   - 올리기 전 최신 main을 머지한다.
   - npm run typecheck && npm run build 등 관련 검사를 직접 돌리고, 무엇을 돌렸고 결과가 어땠는지 PR 본문에 적는다.
   - 무엇을 어떻게 고쳤는지, 못 고친 것과 판단이 필요한 것을 따로 적는다.
   - PR을 올리거나 고친 뒤 검수 전담 세션에 「검수 요청」(PR 번호·head SHA·자체 검수)을 send_message로 보낸다. 검수 전담 ID는 최신 main의 HANDOFF.md 세션 표.
   - main 병합은 검수 전담이 한다. 직접 병합하지 않는다. 검수 전담은 병합하면 올린 세션에 「#N 병합, 다음 진행」을 알린다. 병합 알림 없이 오래 대기 중이면 PR 상태를 직접 조회하고 다음 작업으로 간다. 열린 PR은 1개까지만 두고, 병합된 뒤 다음 작업을 시작한다.
   - 공통 파일(SellerShell.tsx, tokens.css·seller.css 공통 부분, components/admin-ui/**)은 레이아웃 전담만 고친다.
5. 금지: main 직접 푸시, 이력 재작성·강제 푸시, 테스트 삭제·skip, 타입·린트 우회, 운영 DB 테스트 데이터, 비밀값 기록,
   운영 배포·카카오클라우드 자원 변경·유료 자원 생성·실제 결제/환불/적립금 실행 (대표님 승인 전).
   유료 서비스는 쓰지 않는다: 외부 서비스·API는 무료 범위에서만, 한도를 넘으면 멈추는 장치를 둔다(2026-10-05 대표님 지시). 예외: 대표님이 승인한 기능(도우미·자동 연결·외부 쇼핑몰 연동)은 월 1만 원 한도 안에서 쓰고 한도 도달 시 자동으로 멈춘다(2026-10-05).
   비용 부담 주체는 「마스터 관리자 / 파트너스 / 구매자」로만 쓰고 「플랫폼 부담」은 쓰지 않는다. 파트너스 건당 비용은 「발송·이용 충전금」 차감(정본 docs/COST_POLICY.md, 2026-10-05).
6. 대표님 요구사항은 디자인과 개발에 함께 반영된다. 받은 결정이 상대 쪽(디자인↔개발)과 어긋나 보이면 MASTER에 보고한다.
   UI·UX·레이아웃 작업이면 코드보다 먼저 화면 ID→route→최신 디자인 정본/버전→현재 구현을 대조한다. 정본 우선순위와 상세 규칙은 최신 main의 CLAUDE.md 「디자인 정본·구현 동기화·현대화」를 그대로 따른다. 최종 디자인을 못 찾거나 충돌하면 추측 구현하지 않고 BLOCKED: DESIGN_SOURCE_UNRESOLVED로 MASTER에 보고한다.
   확정 디자인의 레이아웃·배치·크기·간격·정렬·색·라운드·타이포 위계·CTA·내비게이션을 임의 재설계하지 않는다. 「현대화」「공통화」「더 좋아 보여서」는 정본을 바꿀 근거가 아니다.
   대표님이 승인한 최신 현대화 규칙이 이전 디자인보다 최신이면 승인된 항목만 우선 적용하고, 디자인 전담과 구현 양쪽을 같은 흐름에서 맞추며 docs/UI_STATUS.md에 동기화 상태를 남긴다. 디자인/구현 한쪽만 바뀐 상태는 완료가 아니다.
   UI PR에는 참조한 디자인 정본/버전과 실제 렌더 증거(기본 1440·1024·390, 화면별 기준이 있으면 그 기준)를 남긴다. 정본과 주요 구조·크기·정보 위계·CTA·내비게이션이 다른 상태는 UI PR의 병합 차단 결함이다.
   파일 존재·CI 성공만으로 완료라고 하지 않는다. 실제 동작 증거를 붙인다.
7. 막힘·실패·위험·대표님 선택 필요 사항은 MASTER로 create_trigger 1회 보고한다.
   MASTER 세션 ID는 최신 main의 HANDOFF.md 세션 표에서 확인한다 (2026-10-06 인수 기준: 01a10187-33d2-70d0-951f-e2d69fdd2dc1).
   담을 것: 무슨 일인지 한 줄 / 무엇이 안 되는지·영향 범위 / 선택지와 권고안 / 근거 파일·줄 또는 실행 링크. 비밀값은 적지 않는다.
```
