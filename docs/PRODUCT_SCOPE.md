# Product Scope

## 목표

판매자별 쇼핑몰과 라이브 방송 운영을 하나로 제공하는 구독 플랫폼.

## 기능 범위

### 쇼핑몰

- 판매자별 쇼핑몰
- 쇼핑몰 주소 (2026-10-02 대표님 결정): 가입 즉시 플랫폼 하위 기본 주소 제공 + 판매자가 직접 산 도메인(.com, .co.kr 등) 연결. 판매자가 도메인 회사에 연결 값을 넣고 플랫폼이 소유 확인 후 보안 인증서를 자동 발급
- 상품·이미지·재고 관리
- 주문 관리
- 구매자 → 판매자 문의 (2026-10-02 대표님 지시): 상품 문의(상품 상세에서, 공개·비공개 선택)와 1:1 문의(마이페이지). 판매자가 관리자에서 답변하고, 답변이 달리면 구매자에게 알림. 해당 판매자와 마스터만 볼 수 있고 다른 판매자는 볼 수 없음
- 판매자 명의 PG 연결 (플랫폼이 대금을 수취하지 않는 구조 전제)
- 구매자 계정 (2026-10-02 대표님 확정): 회원만 주문할 수 있다(비회원 주문 없음). 회원가입 시 PASS 본인인증 필수 (2026-10-02 대표님 지시). 판매자 가입 신청 시 대표자도 PASS 본인인증. 대표자 1명은 쇼핑몰 1개만 열 수 있다(대표자 CI 기준, 해지된 쇼핑몰은 제외. 2026-10-02 대표님 지시). 본인인증 결과(CI)로 같은 쇼핑몰 중복 가입을 막는다
- 로그인 (2026-10-02 대표님 결정): 마스터·판매자·구매자 모두 아이디(이메일)와 비밀번호가 맞으면 바로 로그인한다. 2단계 인증, 로그인 실패 잠금, 접속 IP·네트워크 제한(지정 IP)은 두지 않는다. 로그인 실패는 감사 로그에 남긴다. 판매자 비밀번호 찾기는 대표자 PASS 본인인증으로 하고, 인증한 사람이 그 쇼핑몰 대표자와 같으면(CI 일치) 바로 새 비밀번호를 입력한다. 메일 링크는 쓰지 않는다. 직원 계정은 대표자가 직원 계정 관리에서 재설정한다.
- PASS 인증 횟수 제한 (2026-10-02 대표님 결정): 판매자 비밀번호 찾기의 PASS 본인인증 시작은 쇼핑몰 하나당 하루 10회까지다(KST 자정 초기화). 넘으면 「오늘은 더 인증할 수 없어요. 내일 다시 시도해 주세요」를 보여 주고, 초과 시도는 감사 로그에 남긴다
- 구매자 알림 (2026-10-02 대표님 확정): 카카오 알림톡으로 보내고 실패하면 문자로 대신 보낸다. 「내 차례 알림」은 두지 않는다(대표님 결정 2026-10-02 변경)
- 구매자 메일 (2026-10-02 대표님 결정): 알림톡·문자와 함께 가입 이메일로 주문 메일을 보낸다. 종류는 주문 완료 · 발송(송장 조회 버튼) · 배송 완료 · 취소·환불 4가지. 받는 분 이름·연락처·주소는 가리지 않고 그대로 보여 준다(대표님 결정). 문구는 해요체. 판매자가 종류별로 켜고 끌 수 있다(SA-080). 메일 발송 업체·비용은 대표님 승인 대상
- 개인정보 표시 (2026-10-02 대표님 결정): 판매자·마스터 관리 화면(주문, 배송, 회원, 문의 등)과 주문 메일에서 구매자 이름·연락처·주소를 가리지 않고 그대로 보여 준다. 열람·내보내기는 감사 로그에 남긴다. 다른 구매자에게 공개되는 화면(상품 문의 작성자 등)은 방송 닉네임만 보여 준다
- 판매자 직원 계정 (2026-10-02 대표님 결정): 고정 역할(매니저·방송 담당)로 나누지 않고 권한 항목으로 나눈다. 쇼핑몰 대표자가 직원 계정을 직접 만들고, 항목별로 권한을 켜고 끈다. 항목: 방송 진행(주문대기·개봉) · 오버레이 편집 · 상품 · 주문·배송 · 고객 정보 보기(이름·연락처·주소) · 회원·적립금 · 문의 답변 · 영수증·세금계산서 · 매출 보기 · 쇼핑몰 설정. 결제(PG) 연결·구독·직원 관리·실지급 스위치는 대표자만. 자주 쓰는 묶음(예: 「방송만」)은 버튼으로 한 번에 고를 수 있다. 권한 변경은 감사 로그에 남긴다
- 판매자 가입 순서 (2026-10-02 대표님 결정): 가입 신청 → 마스터 승인 → 승인 안내(메일·알림톡) → 판매자 로그인 → 체험(14일 무료) → 체험이 끝나면 구독 결제 후 계속 사용. 로그인 아이디(이메일)와 비밀번호는 판매자가 가입 신청 때 직접 정한다(플랫폼이 초기 비밀번호를 만들어 주지 않는다). 승인 안내에는 판매자 관리자 주소와 로그인 이메일, 다음 할 일을 담는다. 첫 로그인 때 「시작하기」 체크리스트(쇼핑몰 정보 → PG 연결 → 상품 등록 → 오버레이 주소 복사)를 보여 준다
- 체험 (2026-10-02 대표님 결정 · 같은 날 3일 → 14일로 변경, 화면 표기는 「체험하기」 — 「무료 이용」이라고 쓰지 않는다): 마스터가 가입을 승인한 시각부터 14일(2주) 동안 무료로 쓴다(신청일 기준 아님). 14일이 지나면 구독을 결제해야 판매자 관리자 기능을 계속 쓸 수 있다(결제 전에는 구독·결제 화면과 로그아웃만 열림). 결제하면 바로 이어서 쓴다
- 결제 실패·잠금·해지 (2026-10-02 대표님 결정): 구독료 결제가 실패하면 하루 간격으로 3번 다시 시도하고, 실패한 날부터 7일 유예 뒤 잠근다(쇼핑몰·오버레이 멈춤, 결제하면 바로 풀림). 잠긴 지 30일이 지나면 자동 해지한다. 해지 뒤 90일 동안 데이터를 보관하고 그 뒤 삭제한다. 보관 기간 안에 다시 구독하면 데이터를 그대로 되살린다. 주문·결제 기록은 법정 보존 기간(5년) 동안 따로 보관한다. 해지·삭제 전에 판매자에게 메일·알림톡으로 미리 알린다
- 구독 기간 계산 (2026-10-02 대표님 결정): 구독 기간은 원래 결제일에 이어서 센다. 결제 실패 후 유예·잠금 중에 결제해도 새 기간은 원래 결제일부터 시작한다(잠겨서 못 쓴 날도 기간에 포함). 예약 실행 지연 등 플랫폼 쪽 사정으로는 판매자를 잠그지 않는다
- 가격 변경 적용 (2026-10-02 대표님 결정): 가격을 바꾸면 새로 가입하는 판매자에게는 바로 적용하고, 기존 구독자에게는 30일 전에 메일·알림톡과 판매자 관리자 공지로 알린 뒤 그다음 결제부터 적용한다. 가격 변경은 대표님(최고관리자)만 한다
- 체험 중 기능 범위 (2026-10-02 대표님 결정): 체험 중에도 구독자와 같은 기능을 모두 연다(상품·쇼핑몰·도메인 연결·PG 연결·오버레이·방송·직원·적립금, 실제 판매 포함). 플랫폼 비용이 드는 것만 한도를 둔다(체험이 14일로 늘어도 한도는 그대로): 알림톡·문자 100건, 구매자 가입 PASS 인증 50건, 이미지 저장 용량 1GB(업체 단가 확정 후 조정). 한도에 닿으면 그 기능만 멈추고 「체험 중에는 ○○건까지예요 · 구독하면 바로 풀려요」를 보여 준다
- 잠금 중 허용 범위 (2026-10-02 대표님 결정): 체험 종료·연체로 잠기면 새 판매만 막는다(쇼핑몰 주문·오버레이·방송·상품 등록·도메인 신규 연결). 이미 받은 주문의 배송·취소·환불·구매자 문의 답변·영수증 발행, 구독·결제, 로그아웃은 계속 연다. 구매자 화면에는 「지금은 쇼핑몰을 이용할 수 없어요」만 보이고 판매자 사정은 드러내지 않는다. 자동 해지되면 연결 도메인도 풀고 인증서 갱신을 멈춘다(다시 구독하면 되살림)
- 판매 방식과 환불 고지 (2026-10-02 대표님 결정, 같은 날 「두지 않음」 결정을 뒤집음): 유튜브 라이브에서 판매자가 구매자 대신 개봉(대리 개봉)하고, 상품은 개봉된 상태로 배송한다. 상품 상세와 주문서에 「개봉하면 취소·환불이 안 돼요」를 보여 주고, 결제 전에 동의 체크를 받는다(체크 안 하면 결제 불가). 동의 시각과 문구 버전을 주문마다 기록한다. 개봉 전 주문 취소는 그대로 가능하다. 배송 사고 등 판매자 판단에 따른 예외 환불은 판매자 관리자에서만 한다
- 무통장 입금·구매 제한 기본값 (2026-10-02 MASTER 결정, 2026-10-03 카페24 방식으로 변경, 판매자가 바꿀 수 있음): 미입금 자동 취소는 카페24처럼 판매자가 일·시간 단위로 기간을 정한다. 기본은 사용·10일(카페24 값). 자동 취소 때 재고는 「취소·반품 시 재고 자동 복구」 설정을 따른다. 기한 1시간 전 알림. 자동 구매 제한은 「미입금 자동 취소 3회 → 30일 주문 막기」 켜짐, 「결제 후 취소 5회 → 30일」 꺼짐. 구매 제한은 주문만 막는다(유튜브 채팅은 플랫폼이 막을 수 없음)
- 주문·재고·배송 규칙은 카페24 방식을 따른다 (2026-10-03 대표님 결정). 카페24처럼 판매자가 설정으로 고르고, 카페24 기본값을 확인하지 못한 항목은 아래 기본값을 쓴다.
  - 재고 차감 기준: 상품별로 「주문 기준」(주문 즉시 차감, 선착순·한정 판매 권장) 또는 「결제 기준」(결제·입금 확인 때 차감)을 고른다. 기본은 결제 기준. 「취소·반품 시 재고 자동 복구」 설정(기본 켜짐)을 둔다
  - 수동 재고 차감 (2026-10-03 대표님 결정): 판매자가 주문 없이 재고를 직접 빼거나 더할 수 있다(방송 이벤트 증정·서비스 등). 「−3 · 이벤트 증정」처럼 수량과 사유를 남기고, 재고 이력에 누가·언제·왜를 기록한다. 재고는 0 아래로 내려가지 않는다
  - 배송비: 무료 · 고정 · 구매 금액 기준 조건부 무료를 MVP로 두고, 구매 금액별·수량별·무게별 차등은 출시 후. 제주·도서산간 지역별 추가 배송비는 따로 붙인다(무료 배송이어도 붙음, 판매자가 0원으로 끌 수 있음). 기본은 고정 3,000원 · 도서산간 +3,000원
  - 반품·교환 배송비: 판매자가 반품 배송비(편도)와 교환 배송비(왕복)를 정한다. 구매자 사정(단순 변심)일 때만 받고, 판매자 사정(불량·오배송)이면 받지 않는다. 구매자 사정 전체 반품이면 처음 낸 배송비는 돌려주지 않고 반품 배송비(편도)를 환불액에서 뺀다. 처음 배송비가 0원이었으면 왕복으로 뺀다. 개봉한 상품은 기존 결정대로 환불하지 않는다
  - 배송 완료: 판매자가 직접 처리하고, 「배송 중 n일 뒤 자동 배송 완료」 설정을 둔다(기본 사용·7일). 택배사 배송 추적 연동은 출시 후(비용 확인 뒤 대표님 결정)
  - 구매 확정: 배송 완료 n일 뒤 자동 구매 확정 설정을 둔다(기본 7일)

### 적립금 (판매자별)

- 신규 개발. 망고TCG 적립금 기능은 참고만 하고 코드는 이식하지 않음
- 판매자별 적립금 정책: 회원 등급별 적립률(카드/무통장 구분), 지급 시작 시점
- 적립금 지급 시점 (2026-10-03 대표님 결정): 판매자가 「결제 즉시 지급」과 「배송 완료 후 지급」 중에서 고른다(기본 배송 완료 후 지급). 결제 즉시 지급한 뒤 취소·환불되면 지급한 적립금을 회수한다(원장에 회수로 남김)
- 주문 결제 완료 시 지급, 취소·환불 시 회수 (자동/수동 회수 모드)
- 판매자별 적립금 원장(지급·회수·실패 이력)과 회원별 잔액
- 구매 랭킹 보너스: 명예의 전당 1위 적립금 보너스는 판매자가 켜고 금액을 정한다 (기본 꺼짐, 2026-10-02 대표님 확정)
- 실지급은 판매자별 실행 스위치(기본 꺼짐)로 통제. 개발·검증 단계에서는 테스트 모드만 사용

### 세금계산서·현금영수증 (2026-10-02 대표님 지시)

- 구매자 → 판매자 쇼핑몰: 무통장·계좌이체 결제 시 주문서에서 현금영수증 신청(소득공제용 휴대폰 번호 / 지출증빙용 사업자등록번호). 사업자 구매자는 세금계산서 신청(사업자 정보 입력). 카드 결제는 카드 매출전표로 대신해 별도 발행하지 않는다
- 발행 주체는 판매자(판매자 명의). 판매자 관리자에서 신청 목록·발행 상태(대기 · 발행 · 실패 · 취소)를 보고, 환불 시 발행 취소(마이너스 발행)를 함께 처리
- 플랫폼 → 판매자 (2026-10-02 대표님 결정): 구독료는 카드 자동결제(정기결제)로만 받는다(계좌이체·무통장 없음). 카드 매출전표가 세금계산서를 대신하므로 구독료 세금계산서는 발행하지 않는다(이중 발행 금지). 판매자는 SA-090에서 카드 매출전표를 내려받는다. 판매자 매출(판매자 → 구매자)의 영수증·세금계산서는 판매자 명의로 판매자가 발행하고, 플랫폼은 발행 기능만 제공한다. 세무 처리는 오픈 전 세무사 확인 권고
- 발행 연동 방식(PG 부가 기능 · 발행 대행 서비스 API · 홈택스 수동)은 미확정 (유료, 대표님 승인)

### 배송·정책 결정 (2026-10-02 대표님 확정, 근거 `docs/FEATURE_GAP.md`)

- 배송: 구매자가 주문할 때 「즉시 발송」 또는 「보관 후 합배송」을 고른다. MVP는 즉시 발송(배송지·배송비·도서산간·송장 입력·발송 알림), 보관·합배송(보관 기한 포함)은 출시 후 1차
- 구매자 가입·배송지 (2026-10-03 대표님 결정): 회원가입은 로그인에 꼭 필요한 기본 정보와 필수 약관 동의만 받는다. 배송지는 가입 때 받지 않고 첫 주문 때 입력받는다. 주문 때 입력한 배송지는 자동으로 저장되고(구매자가 끌 수 있음), 여러 개를 저장해 두고 주문서에서 고른다. 기본 배송지 1개를 지정할 수 있고, 마이페이지에서 추가·수정·삭제한다
- 미성년자 구매: 판매자가 「미성년자 구매 막기」 / 「고지 후 허용」 중 선택(기본 고지 후 허용). PASS 생년월일로 판별, 주문서에 미성년자 취소권 고지
- 방송 시작 알림: 광고성 정보로 보고 마케팅 수신 동의 회원에게만 보낸다. 문구에 (광고) 표기와 수신 거부 방법 포함
- 알림톡·문자·가상계좌 등 건당 비용: 전부 판매자 부담(충전식). 요금제에 포함하지 않는다

### 라이브 운영

- OBS 오버레이 편집기: 판매자가 위젯 위치(드래그 앤 드롭)·크기·모든 속성을 직접 편집, 스냅·스마트 가이드 제공 (2026-10-02 대표님 지시)

- 플랫폼 사용법에 대해서만 답한다 (2026-10-02 대표님 확정: 판매자 본인 데이터 조회 답변은 하지 않음). 마스터가 등록한 답변 근거 문서 안에서 답하고, 범위 밖 질문은 정중히 거절하고 문의하기로 안내한다.

### 플랫폼 마스터 관리자

- **플랫폼 마스터 관리자가 최상위 권한이다. 권한 계층: 마스터 관리자 > 판매자 > 구매자·시청자. 마스터 콘솔은 모든 판매자·쇼핑몰·구독·설정을 다루며, 판매자 권한으로 마스터 콘솔 기능에 접근할 수 없다. 마스터 콘솔 안에서도 역할별 권한을 나눈다: 무제한 조회·변경은 최고관리자(대표님)만, 운영·CS는 담당 기능만, 조회 전용은 변경 불가.** (2026-10-02 대표님 지시)
- 마스터 콘솔 운영 (2026-10-02 대표님 결정): 마스터 콘솔은 대표님 혼자 운영한다. 운영·CS·조회 전용 역할 계정은 지금 만들지 않는다(역할 구조는 코드에 남겨 둔다). 대리 조회 때 구매자 이름·연락처·주소는 그대로 보인다(열람은 감사 로그). 마스터의 반복 업무는 사람이 처리하지 않도록 자동화한다
- 판매자 가입 자동 승인 (2026-10-02 대표님 결정): 가입 신청이 들어오면 자동 점검(대표자 PASS 본인인증, 대표자 CI 중복 = 쇼핑몰 1개 규칙, 국세청 사업자 상태 「계속사업자」와 진위확인(대표자명·개업일 대조), 같은 사업자번호로 운영·신청 중인 쇼핑몰 없음, 통신판매업 신고 조회(공정위))을 돌린다. 모두 통과하면 자동 승인하고 승인 안내를 보낸다. 하나라도 걸리면 승인하지 않고 마스터 콘솔 「확인 필요」에 올려 대표님이 직접 승인·보완 요청·반려한다. 자동 승인도 감사 로그에 남긴다
- 대표·플랫폼 운영팀 전용 통합 관리 콘솔 (판매자 관리자와 분리)
- 판매자 가입 승인·정지, 판매자별 쇼핑몰·구독·PG 연결·방송 현황 조회
- 요금제·구독·구독료 청구 관리, 결제 실패·연체 관리
- 고객지원(문의·공지), 관리자 계정·역할별 권한, 감사 로그
- 판매자 화면 대리 조회는 읽기 전용, 접근 기록 필수

## 연동 업체 후보 (2026-10-02 대표님 제시, 계약 전 · 비용은 대표님 승인)

| 항목 | 후보 | 비용(업체 공개 기준) | 확인할 조건 |
|---|---|---|---|
| PG · 초기 비용 최소 | NICEPAY 베이직 | 카드 3.2%, 가입비·연관리비 0원(프로모션) | 플랫폼 제휴 요금, 정기결제(빌링키) 지원 여부 |
| PG · 수수료 최소 | 페이플 | 카드 1.0~2.9%, 가입비 22만 원(부가세 포함), 보증보험 별도 | 최저 요율 적용 조건, 정기결제(빌링키) |
| PASS 본인인증 | NICE·KCB·SCI 중 견적 후 확정 | 미정 | 같은 조건 견적 비교 |
| 전자세금계산서 API | 홈택스빌 | 건당 30원 | 최소요금·가입비, 여러 판매자 대리발행 계약 |
| 현금영수증 API | 볼타 | 발행 무료 | 발급자 등록·공동인증서 필요, 부분취소 미지원 |
| 이메일(소량) | Resend | 월 3,000통 무료 | 하루 100통 제한 |
| 이메일(유료) | AWS SES 종량제 | 1,000통당 0.10달러 | 첨부·부가 기능 별도 |

- PG 수수료와 세금계산서 건당 요금은 부가세 별도다.
- 연동 시 확인할 것(MASTER):
  - PG는 두 용도로 쓰인다. ① 플랫폼 구독료 카드 자동결제(빌링키 필수), ② 판매자 쇼핑몰 결제(판매자 명의). ②는 판매자마다 고른 PG를 연결하므로 여러 PG를 지원할 수 있게 만든다.
  - 볼타는 부분취소를 지원하지 않는다. 주문 일부 취소 때 현금영수증 처리 방법(전체 취소 후 재발행 등)을 확인한다.
  - Resend 하루 100통은 방송 날 주문 메일을 감당하지 못할 수 있다. 운영 발송은 AWS SES를 주로 쓰고, Resend는 개발·테스트용으로 둔다.
  - 판매자 명의 세금계산서·현금영수증은 판매자별 발급자 등록·인증서가 필요하다. 판매자 설정 화면에서 받는다.
