# Product Scope

## 목표

판매자별 쇼핑몰과 라이브 방송 운영을 하나로 제공하는 구독 플랫폼.

## 기능 범위

### 쇼핑몰

- 판매자별 쇼핑몰
- 쇼핑몰 주소 (2026-10-02 대표님 결정): 가입 즉시 플랫폼 하위 기본 주소 제공 + 판매자가 직접 산 도메인(.com, .co.kr 등) 연결. 판매자가 도메인 회사에 연결 값을 넣고 플랫폼이 소유 확인 후 보안 인증서를 자동 발급
- 상품·이미지·재고 관리
- 주문 관리
- 구매자 → 판매자 문의 (2026-10-02 대표님 지시): 상품 문의(상품 상세에서, 공개·비공개 선택)와 1:1 문의(마이페이지). 판매자가 관리자에서 답변하고, 답변이 달리면 구매자에게 알림. 해당 판매자와 마스터만 볼 수 있고 다른 판매자는 볼 수 없음
- 판매자 명의 PG 연결 (플랫폼이 대금을 수취하지 않는 구조 전제)
- 구매자 계정 (2026-10-02 대표님 확정): 회원만 주문할 수 있다(비회원 주문 없음). 회원가입 시 휴대폰 본인확인 필수 (2026-10-02 대표님 지시, 2026-10-03 PASS 앱 방식에서 문자 방식으로 변경). 판매자 가입 신청 시 대표자도 휴대폰 본인확인. 대표자 1명은 쇼핑몰 1개만 열 수 있다(대표자 CI 기준, 해지된 쇼핑몰은 제외. 2026-10-02 대표님 지시). 본인인증 결과(CI)로 같은 쇼핑몰 중복 가입을 막는다
- 로그인 (2026-10-02 대표님 결정, 2026-10-03 로그인 잠금 없음 재확인): 마스터·판매자·구매자 모두 아이디(이메일)와 비밀번호가 맞으면 바로 로그인한다. 2단계 인증, 로그인 실패 잠금, 접속 IP·네트워크 제한(지정 IP)은 두지 않는다. 로그인 실패는 감사 로그에 남긴다. 판매자 비밀번호 찾기는 대표자 휴대폰 본인확인으로 하고, 인증한 사람이 그 쇼핑몰 대표자와 같으면(CI 일치) 바로 새 비밀번호를 입력한다. 메일 링크는 쓰지 않는다. 직원 계정은 대표자가 직원 계정 관리에서 재설정한다.
- 본인확인 횟수 제한 (2026-10-02 대표님 결정, 2026-10-03 휴대폰 본인확인으로 명칭 변경): 판매자 비밀번호 찾기의 휴대폰 본인확인 시작은 쇼핑몰 하나당 하루 10회까지다(KST 자정 초기화). 넘으면 「오늘은 더 인증할 수 없어요. 내일 다시 시도해 주세요」를 보여 주고, 초과 시도는 감사 로그에 남긴다
- 구매자 알림 (2026-10-02 대표님 확정): 카카오 알림톡으로 보내고 실패하면 문자로 대신 보낸다. 「내 차례 알림」은 두지 않는다(대표님 결정 2026-10-02 변경)
- 구매자 메일 (2026-10-02 대표님 결정): 알림톡·문자와 함께 가입 이메일로 주문 메일을 보낸다. 종류는 주문 완료 · 발송(송장 조회 버튼) · 배송 완료 · 취소·환불 4가지. 받는 분 이름·연락처·주소는 가리지 않고 그대로 보여 준다(대표님 결정). 문구는 해요체. 판매자가 종류별로 켜고 끌 수 있다(SA-080). 메일 발송 업체·비용은 대표님 승인 대상
- 개인정보 표시 (2026-10-02 대표님 결정): 판매자·마스터 관리 화면(주문, 배송, 회원, 문의 등)과 주문 메일에서 구매자 이름·연락처·주소를 가리지 않고 그대로 보여 준다. 열람·내보내기는 감사 로그에 남긴다. 다른 구매자에게 공개되는 화면(상품 문의 작성자 등)은 방송 닉네임만 보여 준다
- 판매자 직원 계정 (2026-10-02 대표님 결정): 고정 역할(매니저·방송 담당)로 나누지 않고 권한 항목으로 나눈다. 쇼핑몰 대표자가 직원 계정을 직접 만들고, 항목별로 권한을 켜고 끈다. 항목: 방송 진행(주문대기·개봉) · 오버레이 편집 · 상품 · 주문·배송 · 고객 정보 보기(이름·연락처·주소) · 회원·적립금 · 문의 답변 · 영수증·세금계산서 · 매출 보기 · 쇼핑몰 설정. 결제(PG) 연결·구독·직원 관리·실지급 스위치는 대표자만. 자주 쓰는 묶음(예: 「방송만」)은 버튼으로 한 번에 고를 수 있다. 권한 변경은 감사 로그에 남긴다
- 판매자 가입 순서 (2026-10-02 대표님 결정): 가입 신청 → 마스터 승인 → 승인 안내(메일·알림톡) → 판매자 로그인 → 체험(14일 무료) → 체험이 끝나면 구독 결제 후 계속 사용. 로그인 아이디(이메일)와 비밀번호는 판매자가 가입 신청 때 직접 정한다(플랫폼이 초기 비밀번호를 만들어 주지 않는다). 승인 안내에는 판매자 관리자 주소와 로그인 이메일, 다음 할 일을 담는다. 첫 로그인 때 「시작하기」 체크리스트(쇼핑몰 정보 → PG 연결 → 상품 등록 → 오버레이 주소 복사)를 보여 준다
- 체험 (2026-10-02 대표님 결정 · 같은 날 3일 → 14일로 변경, 화면 표기는 「체험하기」 — 「무료 이용」이라고 쓰지 않는다): 마스터가 가입을 승인한 시각부터 14일(2주) 동안 무료로 쓴다(신청일 기준 아님). 14일이 지나면 구독을 결제해야 판매자 관리자 기능을 계속 쓸 수 있다(결제 전에는 구독·결제 화면과 로그아웃만 열림). 결제하면 바로 이어서 쓴다
- 결제 실패·잠금·해지 (2026-10-02 대표님 결정): 구독료 결제가 실패하면 하루 간격으로 3번 다시 시도하고, 실패한 날부터 7일 유예 뒤 잠근다(쇼핑몰·오버레이 멈춤, 결제하면 바로 풀림). 잠긴 지 30일이 지나면 자동 해지한다. 해지 뒤 90일 동안 데이터를 보관하고 그 뒤 삭제한다. 보관 기간 안에 다시 구독하면 데이터를 그대로 되살린다. 주문·결제 기록은 법정 보존 기간(5년) 동안 따로 보관한다. 해지·삭제 전에 판매자에게 메일·알림톡으로 미리 알린다
- 구독 기간 계산 (2026-10-02 대표님 결정): 구독 기간은 원래 결제일에 이어서 센다. 결제 실패 후 유예·잠금 중에 결제해도 새 기간은 원래 결제일부터 시작한다(잠겨서 못 쓴 날도 기간에 포함). 예약 실행 지연 등 플랫폼 쪽 사정으로는 판매자를 잠그지 않는다
- 가격 변경 적용 (2026-10-02 대표님 결정): 가격을 바꾸면 새로 가입하는 판매자에게는 바로 적용하고, 기존 구독자에게는 30일 전에 메일·알림톡과 판매자 관리자 공지로 알린 뒤 그다음 결제부터 적용한다. 가격 변경은 대표님(최고관리자)만 한다
- 체험 중 기능 범위 (2026-10-02 대표님 결정): 체험 중에도 구독자와 같은 기능을 모두 연다(상품·쇼핑몰·도메인 연결·PG 연결·오버레이·방송·직원·적립금, 실제 판매 포함). 플랫폼 비용이 드는 것만 한도를 둔다(체험이 14일로 늘어도 한도는 그대로): 알림톡·문자 100건, 구매자 가입 휴대폰 본인확인 50건(주문 알림 문자 발송량과 따로 셈), 이미지 저장 용량 1GB(업체 단가 확정 후 조정). 한도에 닿으면 그 기능만 멈추고 「체험 중에는 ○○건까지예요 · 구독하면 바로 풀려요」를 보여 준다
- 잠금 중 허용 범위 (2026-10-02 대표님 결정): 체험 종료·연체로 잠기면 새 판매만 막는다(쇼핑몰 주문·오버레이·방송·상품 등록·도메인 신규 연결). 이미 받은 주문의 배송·취소·환불·구매자 문의 답변·영수증 발행, 구독·결제, 로그아웃은 계속 연다. 구매자 화면에는 「지금은 쇼핑몰을 이용할 수 없어요」만 보이고 판매자 사정은 드러내지 않는다. 자동 해지되면 연결 도메인도 풀고 인증서 갱신을 멈춘다(다시 구독하면 되살림)
- 판매 방식과 환불 고지 (2026-10-02 대표님 결정, 같은 날 「두지 않음」 결정을 뒤집음): 유튜브 라이브에서 판매자가 구매자 대신 개봉(대리 개봉)하고, 상품은 개봉된 상태로 배송한다. 상품 상세와 주문서에 개봉 고지(아래 문구)를 보여 주고, 결제 전에 동의 체크를 받는다(체크 안 하면 결제 불가). 동의 시각과 문구 버전을 주문마다 기록한다. 개봉 전 주문 취소는 그대로 가능하다. 배송 사고 등 판매자 판단에 따른 예외 환불은 판매자 관리자에서만 한다. 다만 상품이 표시·광고나 계약 내용과 다르거나(오배송·불량 포함) 판매자 사정인 경우에는 개봉했어도 법에 따라 청약철회·환불을 받을 수 있으므로(전자상거래법 제17조 제3항), 고지·동의 문구에 이 예외를 함께 적는다 (2026-10-03 MASTER 보완, 대표님 확인 필요): 「개봉하면 단순 변심으로는 취소·환불이 안 돼요. 상품이 설명과 다르거나 잘못 왔으면 환불받을 수 있어요」
- 무통장 입금·구매 제한 기본값 (2026-10-02 MASTER 결정, 2026-10-03 카페24 방식으로 변경, 같은 날 대표님 지시로 기본 기한 24시간, 판매자가 바꿀 수 있음): 미입금 자동 취소는 카페24처럼 판매자가 일·시간 단위로 기간을 정한다. 기본은 사용·주문 후 24시간. 자동 취소 때 재고는 「취소·반품 시 재고 자동 복구」 설정을 따른다. 기한 하루 전 알림(기간이 하루 이하면 1시간 전). 자동 구매 제한은 「미입금 자동 취소 3회 → 30일 주문 막기」 켜짐, 「결제 후 취소 5회 → 30일」 꺼짐. 구매 제한은 주문만 막는다(유튜브 채팅은 플랫폼이 막을 수 없음)
- 주문·재고·배송 규칙은 카페24 방식을 따른다 (2026-10-03 대표님 결정). 카페24처럼 판매자가 설정으로 고르고, 카페24 기본값을 확인하지 못한 항목은 아래 기본값을 쓴다.
  - 재고 차감 기준: 상품별로 「주문 기준」(주문 즉시 차감, 선착순·한정 판매 권장) 또는 「결제 기준」(결제·입금 확인 때 차감)을 고른다. 기본은 결제 기준. 「취소·반품 시 재고 자동 복구」 설정(기본 켜짐)을 둔다
  - 수동 재고 차감 (2026-10-03 대표님 결정): 판매자가 주문 없이 재고를 직접 빼거나 더할 수 있다(방송 이벤트 증정·서비스 등). 「−3 · 이벤트 증정」처럼 수량과 사유를 남기고, 재고 이력에 누가·언제·왜를 기록한다. 재고는 0 아래로 내려가지 않는다
  - 「재고 적음」 기준은 옵션 재고 합계 1~5개(지금은 고정값 `LOW_STOCK_MAX`). 추후 판매자 설정으로 바꿀 수 있게 한다 (2026-10-03 MASTER 검수)
  - 배송비: 무료 · 고정 · 구매 금액 기준 조건부 무료를 MVP로 두고, 구매 금액별·수량별·무게별 차등은 출시 후. 제주·도서산간 지역별 추가 배송비는 따로 붙인다(무료 배송이어도 붙음, 판매자가 0원으로 끌 수 있음). 기본은 고정 3,000원 · 도서산간 +3,000원
  - 반품·교환 배송비: 판매자가 반품 배송비(편도)와 교환 배송비(왕복)를 정한다. 구매자 사정(단순 변심)일 때만 받고, 판매자 사정(불량·오배송)이면 받지 않는다. 구매자 사정 전체 반품이면 처음 낸 배송비는 돌려주지 않고 반품 배송비(편도)를 환불액에서 뺀다. 처음 배송비가 0원이었으면 왕복으로 뺀다. 개봉한 상품은 구매자 사정(단순 변심)으로는 환불하지 않는다. 표시·광고·계약과 다르거나 판매자 사정(불량·오배송)이면 개봉했어도 환불한다(위 「판매 방식과 환불 고지」 예외)
  - 배송 완료: 판매자가 직접 처리하고, 「배송 중 n일 뒤 자동 배송 완료」 설정을 둔다(기본 사용·7일). 택배사 배송 추적 연동은 출시 후(비용 확인 뒤 대표님 결정). 조회 업체는 스마트택배(스윗트래커, 키 `SWEETTRACKER_API_KEY`). 무료 제공 건수를 다 쓰면 유료로 넘어가지 않고 조회를 멈춘 뒤 대표님께 보고한다(2026-10-03 대표님 지시). 사용 건수는 플랫폼이 직접 세서 무료 한도에 가까워지면 미리 알린다
  - 구매 확정: 배송 완료 n일 뒤 자동 구매 확정 설정을 둔다(기본 7일)
  - 구매 확정 뒤 환불 (2026-10-03 대표님 결정, 카페24 방식): 구매 확정한 주문은 바로 취소·반품·환불할 수 없다. 판매자가 주문 상세에서 「구매 확정 취소」를 하면 환불할 수 있다. 이 주문으로 이미 지급한 적립금(결제 즉시 또는 배송 완료 후 지급)은 기존 회수 정책(판매자 설정 자동·수동)대로 회수한다. 구매 확정은 시각만 남기고 적립금을 따로 지급하지 않는다(망고TCG 이용안내 「주문취소/환불시에 상품구매로 적립된 적립금은 함께 취소」와 같음)
- 구매자 탈퇴·재가입 (2026-10-03 대표님 결정, 카페24 방식)
  - 탈퇴하면 남은 적립금은 사라지고, 다시 가입해도 돌아오지 않는다. 탈퇴 화면에서 미리 알린다
  - 탈퇴하면 회원 정보(로그인 아이디·비밀번호·연락처 등 계정 정보)는 바로 파기하거나 알아볼 수 없게 한다. 법으로 보관해야 하는 기록만 그 종류별 기간 동안 따로 분리해 보관하고 기간이 끝나면 파기한다: 계약·청약철회 기록 5년, 대금 결제·재화 공급 기록 5년, 소비자 불만·분쟁 처리 기록 3년, 표시·광고 기록 6개월, 접속 기록 3개월. 거래가 없는 회원은 거래 기록이 남지 않는다(위 접속 기록 3개월만 보관). 구매자가 한 일의 감사 로그 IP·브라우저 정보는 접속 기록 보관 기간(3개월)이 지나면 지운다. 판매자 직원·플랫폼 관리자가 개인정보를 다룬 접속 기록(감사 로그)은 이 3개월 삭제 대상이 아니며, 개인정보의 안전성 확보조치 기준 제8조에 따라 최소 1년(법이 정한 경우 2년) 보관한다(FEATURE_GAP). 탈퇴 회원의 감사 로그는 주문 기록과 회원 id로 이어지므로 거래 기록 보관 기간(5년, 거래가 없으면 3개월) 동안 거래 기록의 일부로 보관하고, 그 기간이 끝나면 감사 로그에 들어간 그 회원 id(행위자 id·대상 id 등 모든 칸)를 비식별 값으로 바꾼다. 파기 대상에는 회원 행의 생년월일과, 그 회원의 본인확인 기록이 들어간다. 본인확인 기록은 칸별로 지우지 않고 행 자체를 삭제한다(이름·휴대폰·인증 요청 휴대폰 번호·생년월일·CI 해시·요청 IP·회원 연결(subjectId) 모두 함께 사라짐). 재가입 제한용 CI 해시만 아래 예외로 본인확인 기록이 아닌 재가입 제한 보관 자리에 따로 남긴다. 방송 닉네임은 회원 행뿐 아니라 주문·주문대기·HIT 카드에 복사된 닉네임까지 탈퇴 때 「탈퇴한 회원」으로 바꾼다(닉네임은 법정 보관 기록이 아님). 로그인 세션 기록은 폐기 표시만 하지 않고 탈퇴 때 삭제한다. 원칙: 회원 id를 가진 모든 표는 「탈퇴 때 삭제」·「비식별」·「법정 보관(기간 뒤 파기)」 중 하나로 분류하고, 새 표가 생기면 분류를 빠뜨리지 않도록 표 목록 검사 테스트를 둔다
  - 재가입 제한은 판매자 설정으로 둔다(기본 사용 안 함). 쓰면 판매자가 정한 기간 동안 같은 사람(본인확인 기준)이 다시 가입할 수 없다. 회원마다 가입 때 동의한 제한 기간을 기록하고, 탈퇴 때는 그 기간과 지금 설정 중 짧은 쪽만 적용한다(동의하지 않은 더 긴 기간으로 보관하지 않음). 재가입 제한을 켜기 전에 가입한 회원(별도 동의와 기간 기록이 없는 회원)에게는 적용하지 않는다. 다시 동의를 받는 기능은 만들지 않는다. 이를 위해 재가입 제한이 켜진 쇼핑몰에서만 탈퇴 회원의 본인확인 식별값 해시(ciHash) 하나를 「재가입 제한」 목적으로 제한 기간 동안 남기고, 기간이 끝나면 파기한다. 이름·휴대폰 등 다른 정보는 남기지 않는다. 개인정보처리방침의 보유 기간에 이 항목을 적는다. 가입 화면에서는 이 보관을 「개인정보 수집·이용」과 다른 별도 필수 동의 항목으로 받는다(재가입 제한이 켜진 쇼핑몰만, 동의 기록도 따로 저장). 근거는 이용약관 제6조의 재가입 제한 조항이다
  - 적립금 소멸 (망고TCG 이용안내 기준): 마지막 적립일부터 3년 동안 새 적립이 없으면 남은 적립금이 사라진다. 소멸 30일 전에 알림톡(실패하면 문자)으로 소멸 예정 금액과 날짜를 알린다(이메일 주인 확인 기능이 생기기 전까지 메일로는 보내지 않는다)(카페24 소멸 사전 안내 방식). 소멸은 원장에 소멸 기록으로 남긴다
- 같은 휴대폰 번호 (2026-10-03 대표님 결정, 카페24 휴대폰 회원인증 방식): 한 쇼핑몰에서 한 사람(본인확인)·한 휴대폰 번호로 한 계정만 만든다. 가족이 번호를 같이 쓰면 각자 자기 번호로 본인확인해야 한다
- 이용약관·개인정보처리방침 (2026-10-03 대표님 지시, 망고TCG 쇼핑몰과 같은 서식)
  - 이용약관은 공정위 전자상거래 표준약관(`docs/terms/BUYER_TERMS_TEMPLATE.md`), 개인정보처리방침은 카페24 샘플 서식(`docs/terms/PRIVACY_POLICY_TEMPLATE.md`)을 기본으로 판매자 쇼핑몰마다 상호·책임자·적용일을 채워 쓴다. 판매자가 고칠 수 있고, 버전·시행일과 함께 저장해 동의 기록에 버전을 남긴다
  - 처리방침 「8. 정보주체의 권리」의 열람·정정·삭제 방법은 실제로 있는 화면에 맞춘다: 회원 정보 화면(SH-024, 미구현)이 생기기 전까지는 「쇼핑몰 1:1 문의 또는 개인정보 보호책임자 연락처로 요청하면 본인 확인 뒤 처리」로 쓰고, 탈퇴는 회원 탈퇴 기능으로 한다
  - 우리 서비스에 맞춰 고칠 곳: 서식에 남은 옛 법 조항 인용(정보통신망법 제22조 등, 2020년 삭제)은 현행 개인정보 보호법 조항과 문구로 바꾼다, 비회원 주문 없음(비회원 문구 정리), 간편 로그인 없음, 가입 수집 항목(휴대폰 본인확인 결과·방송 닉네임 등 실제 항목), 위탁 표(플랫폼 운영사·본인확인 대행사·알림톡·문자 발송사·주문 메일 발송사·PG·택배, 실제 쓰는 업체와 맡긴 일을 적음)
  - 야간 광고 (2026-10-03 MASTER 결정, 정보통신망법 제50조 제3항): 광고성 메시지(방송 시작·할인 알림 등)는 알림톡으로 보내지 않는다(카카오 정책상 알림톡은 거래 정보 전용). 카카오로 보낼 때는 친구톡(브랜드 메시지)처럼 광고를 허용하는 상품을, 아니면 문자·메일을 쓴다. 별도 야간 수신 동의는 받지 않고, 광고성 카카오 메시지·문자는 21시~다음 날 8시(KST)에 보내지 않는다. 그 시간에 생긴 알림은 8시 이후로 미루거나 보내지 않는다. 이메일 주인 확인 기능이 생기기 전까지 이메일 광고는 보내지 않는다(가입 이메일은 형식만 확인해서 남의 주소일 수 있음)
  - 선택 동의 「마케팅 정보 수신」은 `docs/terms/MARKETING_CONSENT_TEMPLATE.md`를 보여 주고 그 버전을 동의 기록에 남긴다
  - 가입 때 받는 필수 동의 「개인정보 수집·이용」은 처리방침과 따로 `docs/terms/PRIVACY_CONSENT_TEMPLATE.md`(목적·항목·보유 기간·거부할 권리와 불이익)를 보여 주고 그 버전을 동의 기록에 남긴다
  - 동의 순서 (2026-10-03 MASTER 결정): 필수 동의(이용약관·개인정보 수집·이용, 재가입 제한을 켠 쇼핑몰은 재가입 제한 정보 보관 동의까지)를 휴대폰 본인확인 요청 전에 받는다. 본인확인 시작 API는 동의 여부와 동의한 문서 버전을 함께 받고, 없으면 시작하지 않는다. 가입을 끝내지 않은 본인확인 기록은 확인 유효 시간이 끝나면 지체 없이 파기한다
- 만 14세 미만 가입 (2026-10-03 MASTER 결정, 법정대리인 동의 기능을 만들기 전까지): 본인확인 생년월일 기준 만 14세 미만은 가입할 수 없다. 미구현(HANDOFF 참고). 가입 차단을 구현하기 전에는 이 문구를 처리방침에 쓰지 않는다. 처리방침 서식의 「4. 만 14세 미만 아동」 항목은 「만 14세 미만은 가입할 수 없어요」로 바꿔 쓴다
- 플랫폼 운영사 정보 (2026-10-03 대표님 결정): 플랫폼 화면의 사업자 정보·개인정보 보호책임자·호스팅 제공자 표기는 대표님 사업자 기준으로 한다. 값은 저장소에 적지 않고 마스터 콘솔 설정으로 넣는다
- 상품명 길이 (2026-10-03 대표님 결정, 네이버 스마트스토어·쿠팡 기준 참고): 상품명은 공백 포함 최대 100자. 넘으면 저장하지 않고 안내한다. 입력 칸에 글자 수(예: 42/100)를 보여 주고, 목록에서 잘 보이도록 50자 이내를 권장한다
- 상품 이벤트 할인·마감 임박 표시 (2026-10-03 대표님 결정, 쿠팡·네이버 쇼핑 방식 참고): 판매자가 상품마다 이벤트 할인(할인율 또는 할인 금액)과 시작·종료 시각을 정한다. 기간 동안 정가 취소선 + 할인율 + 할인가를 보여 주고, 끝나면 자동으로 정가로 돌아간다. 종료가 가까우면 「오늘 마감」·「D-3」 배지와 「3시간 12분 남았어요」 같은 남은 시간(타임딜 카운트다운)을 상품 목록·상세·방송 오버레이에 보여 준다. 할인 적용 여부와 금액은 주문할 때 서버가 DB 시계로 판단하고, 주문에 그때 금액을 남긴다(기간이 끝나도 이미 만든 주문 금액은 바뀌지 않음)
  - 할인은 단가(상품 가격 + 옵션 추가금)에 적용하고 할인가는 원 단위 버림이다. 할인율은 1~90%, 할인 금액도 가격의 90%까지. 시각은 오프셋이 붙은 ISO 8601로만 받는다 (2026-10-03 MASTER 검수)

### 적립금 (판매자별)

- 신규 개발. 망고TCG 적립금 기능은 참고만 하고 코드는 이식하지 않음
- 판매자별 적립금 정책: 회원 등급별 적립률(카드/무통장 구분), 지급 시작 시점
- 적립금 지급 시점 (2026-10-03 대표님 결정): 판매자가 「결제 즉시 지급」과 「배송 완료 후 지급」 중에서 고른다(기본 배송 완료 후 지급). 결제 즉시 지급한 뒤 취소·환불되면 지급한 적립금을 회수한다(원장에 회수로 남김)
  - 적립은 결제 시점 스냅숏으로 판정한다(2026-10-03 MASTER 결정): 지급 시점·회원 등급·적립률·적립 예정액을 결제 때 주문에 남기고 지급 시작일도 결제 시각 기준. 배송 완료 후 지급이면 그 예정액을 배송 완료 때 지급 대기로 기록한다. 결제 때 0원이면 나중에도 적립하지 않는다
- 주문 결제 완료 시 지급, 취소·환불 시 회수 (자동/수동 회수 모드)
- 적립 기준 금액 (2026-10-03 대표님 결정): 할인 후 상품 금액에 적립률을 곱한다. 배송비는 빼고, 적립금으로 결제한 금액은 빼지 않는다(예: 할인 후 상품 금액 310,200원 × 3% = 9,306원)
- 판매자별 적립금 원장(지급·회수·실패 이력)과 회원별 잔액
- 구매 랭킹 보너스: 명예의 전당 1위 적립금 보너스는 판매자가 켜고 금액을 정한다 (기본 꺼짐, 2026-10-02 대표님 확정)
- 실지급은 판매자별 실행 스위치(기본 꺼짐)로 통제. 개발·검증 단계에서는 테스트 모드만 사용

### 세금계산서·현금영수증 (2026-10-02 대표님 지시)

- 구매자 → 판매자 쇼핑몰: 무통장·계좌이체 결제 시 주문서에서 현금영수증 신청(소득공제용 휴대폰 번호 / 지출증빙용 사업자등록번호). 사업자 구매자는 세금계산서 신청(사업자 정보 입력). 카드 결제는 카드 매출전표로 대신해 별도 발행하지 않는다
- 발행 주체는 판매자(판매자 명의). 판매자 관리자에서 신청 목록·발행 상태(대기 · 발행 · 실패 · 취소)를 보고, 환불 시 발행 취소(마이너스 발행)를 함께 처리
- 플랫폼 → 판매자 (2026-10-02 대표님 결정): 구독료는 카드 자동결제(정기결제)로만 받는다(계좌이체·무통장 없음). 카드 매출전표가 세금계산서를 대신하므로 구독료 세금계산서는 발행하지 않는다(이중 발행 금지). 판매자는 SA-090에서 카드 매출전표를 내려받는다. 판매자 매출(판매자 → 구매자)의 영수증·세금계산서는 판매자 명의로 판매자가 발행하고, 플랫폼은 발행 기능만 제공한다. 세무 처리는 오픈 전 세무사 확인 권고
- 발행 연동 방식 (2026-10-03 대표님 결정): 발행 대행 서비스 API로 하고 업체는 바로빌이다(키 `BAROBILL_API_KEY`). 요금·계약 조건은 연동 전에 확인한다(유료, 대표님 승인)

### 배송·정책 결정 (2026-10-02 대표님 확정, 근거 `docs/FEATURE_GAP.md`)

- 배송: 구매자가 주문할 때 「즉시 발송」 또는 「보관 후 합배송」을 고른다. MVP는 즉시 발송(배송지·배송비·도서산간·송장 입력·발송 알림), 보관·합배송(보관 기한 포함)은 출시 후 1차
- 구매자 가입·배송지 (2026-10-03 대표님 결정): 회원가입은 로그인에 꼭 필요한 기본 정보와 필수 약관 동의만 받는다. 배송지는 가입 때 받지 않고 첫 주문 때 입력받는다. 주문 때 입력한 배송지는 자동으로 저장되고(구매자가 끌 수 있음), 여러 개를 저장해 두고 주문서에서 고른다. 기본 배송지 1개를 지정할 수 있고, 마이페이지에서 추가·수정·삭제한다
  - 우편번호·주소 입력 (2026-10-03 대표님 지시): 카카오(다음) 우편번호 서비스로 검색해 우편번호·도로명 주소를 채운다(무료·키 없음). 구매자는 상세 주소만 직접 쓴다. 서버는 받은 값을 지금처럼 다시 검사하고 도서산간도 서버가 판정한다(화면 값만 믿지 않음). 검색창을 못 띄우면 직접 입력으로 대신한다. 판매자 출고지·반품지 주소도 같은 방식
    - 적용 기준(카카오 우편번호 서비스 가이드 https://postcode.map.kakao.com/guide): 스크립트 `https://t1.daumcdn.net/mapjsapi/bundle/postcode/prod/postcode.v2.js`를 주소 검색을 열 때만 불러온다. 키 발급 없음. 팝업 차단을 피하려고 PC는 레이어, 모바일은 전체 화면에 embed로 띄운다. 결과의 `zonecode`(5자리)를 우편번호로, `roadAddress`를 기본 주소로 쓴다(구매자가 지번을 고르면 `jibunAddress`). 공동주택이면 `buildingName`을 괄호로 덧붙인다. 다 고르면 상세 주소 칸으로 포커스를 옮긴다. 가이드 원문은 MASTER 환경에서 접속이 막혀 공개 자료로 확인했고, 구현 때 화면 세션이 원문과 다시 맞춘다
- 구매자 화면은 반응형 웹만 만든다. 별도 앱은 만들지 않는다 (2026-10-03 대표님 결정). 알림은 알림톡·문자·메일로 보낸다
- 미성년자 구매: 판매자가 「미성년자 구매 막기」 / 「고지 후 허용」 중 선택(기본 고지 후 허용). 휴대폰 본인확인 생년월일로 판별, 주문서에 미성년자 취소권 고지
- 방송 시작 알림: 광고성 정보로 보고 마케팅 수신 동의 회원에게만 보낸다. 문구에 (광고) 표기와 수신 거부 방법 포함
- 알림톡·문자·가상계좌 등 건당 비용: 전부 판매자 부담(충전식). 요금제에 포함하지 않는다

### 플랫폼 마스터 관리자

- **플랫폼 마스터 관리자가 최상위 권한이다. 권한 계층: 마스터 관리자 > 판매자 > 구매자·시청자. 마스터 콘솔은 모든 판매자·쇼핑몰·구독·설정을 다루며, 판매자 권한으로 마스터 콘솔 기능에 접근할 수 없다. 마스터 콘솔 안에서도 역할별 권한을 나눈다: 무제한 조회·변경은 최고관리자(대표님)만, 운영·CS는 담당 기능만, 조회 전용은 변경 불가.** (2026-10-02 대표님 지시)
- 마스터 콘솔 운영 (2026-10-02 대표님 결정): 마스터 콘솔은 대표님 혼자 운영한다. 운영·CS·조회 전용 역할 계정은 지금 만들지 않는다(역할 구조는 코드에 남겨 둔다). 대리 조회 때 구매자 이름·연락처·주소는 그대로 보인다(열람은 감사 로그). 마스터의 반복 업무는 사람이 처리하지 않도록 자동화한다
- 휴대폰 본인확인 방식 (2026-10-03 대표님 결정): PASS 앱 설치·실행·앱 전환을 요구하지 않고, 본인확인기관 대행사의 정식 「문자로 본인확인」(명의 정보 대조 + 문자 인증번호 입력)으로 한다. 일반 문자 발송 API로 번호 소유만 확인하는 방식은 쓰지 않는다. 화면 명칭은 「휴대폰 본인확인」, 방식 설명은 「문자로 본인확인」
  - 화면: 대행사가 허용하면 자체 화면(인적사항 입력 → 약관 동의 → 인증번호 받기 → 인증 확인), 허용하지 않으면 대행사 공식 인증창(PC 팝업·모바일 페이지 전환). 주민등록번호 전체는 받지 않는다. 자릿수·유효시간·재전송 규칙은 대행사 규격을 따른다
  - 문자 단독(PASS 선택지 없음) 제공이 계약·기술상 가능한지 대행사 확인 전까지는 차단 조건이다. 확인 전에는 「PASS 없이 문자만」이라고 안내하지 않는다
  - 후보 구성 (2026-10-03 MASTER 조사, 포트원 공개 문서 기준): 포트원 V2 + NHN KCP 채널 「API 방식」. 서버가 인증번호 요청(`method: SMS`) → 사용자가 자체 화면에 인증번호 입력 → 서버가 확인 → 서버 단건 조회로 `VERIFIED` 확정. 같은 요청 id는 한 번만 성공한다. 입력은 이름·휴대폰번호·생년월일과 성별 자리(주민번호 앞 7자리)·통신사(알뜰폰 포함). KCP 표준창은 인증 수단을 문자로 제한하는 설정이 문서에 없다. KCP 원문 가이드·NICE·KCB·SCI 문서는 접속이 막혀 확인하지 못했다
  - 결과는 서버 간 조회·복호화로만 확정한다(브라우저 성공 표시·콜백 값만으로 완료하지 않음). 요청은 현재 가입 세션에 묶고, 다른 사용자 결과 재사용·같은 결과 반복 사용·만료 결과를 막는다. 완료 뒤 휴대폰번호 등 인증 대상 정보가 바뀌면 다시 인증한다
  - 인증 이력에는 대행사·방식·완료 시각을 남긴다. 과거 이력의 방식은 바꾸지 않는다. 사용량은 인증 성공 1건을 한 번만 세고, 대행사 과금 건수와 따로 본다
  - 운영에서 계약·키·필수 설정이 없으면 「본인확인 서비스 준비 중」으로 안내하고 가입을 막는다. 가짜 인증은 개발·테스트에서만 쓴다
  - 휴대폰 본인확인은 사업자 확인·판매자 승인·PG 승인과 별개다. 본인확인 성공만으로 승인·정산 가능 상태를 만들지 않는다
- 판매자 가입 자동 승인 (2026-10-02 대표님 결정): 가입 신청이 들어오면 자동 점검(대표자 휴대폰 본인확인, 대표자 CI 중복 = 쇼핑몰 1개 규칙, 국세청 사업자 상태 「계속사업자」와 진위확인(대표자명·개업일 대조), 같은 사업자번호로 운영·신청 중인 쇼핑몰 없음, 통신판매업 신고 조회(공정위))을 돌린다. 모두 통과하면 자동 승인하고 승인 안내를 보낸다. 하나라도 걸리면 승인하지 않고 마스터 콘솔 「확인 필요」에 올려 대표님이 직접 승인·보완 요청·반려한다. 자동 승인도 감사 로그에 남긴다
- 대표·플랫폼 운영팀 전용 통합 관리 콘솔 (판매자 관리자와 분리)
- 판매자 가입 승인·정지, 판매자별 쇼핑몰·구독·PG 연결·방송 현황 조회
- 요금제·구독·구독료 청구 관리, 결제 실패·연체 관리
- 고객지원(문의·공지), 관리자 계정·역할별 권한, 감사 로그
- 판매자 화면 대리 조회는 읽기 전용, 접근 기록 필수

- 연동 시 확인할 것(MASTER):
  - PG는 두 용도로 쓰인다. ① 플랫폼 구독료 카드 자동결제(빌링키 필수), ② 판매자 쇼핑몰 결제(판매자 명의). ②는 판매자마다 고른 PG를 연결하므로 여러 PG를 지원할 수 있게 만든다.
  - 바로빌로 세금계산서·현금영수증을 함께 발행한다. 주문 일부 취소 때 현금영수증 부분취소 지원 여부를 연동 때 확인한다.
  - Resend 하루 100통은 방송 날 주문 메일을 감당하지 못할 수 있다. 운영 발송은 AWS SES를 주로 쓰고, Resend는 개발·테스트용으로 둔다(실제 구매자 정보는 Resend로 보내지 않는다: Resend는 미국에서 처리해 국외 이전 고지가 필요하다. 운영 SES는 서울 리전(ap-northeast-2)을 쓴다. 국외 리전·국외 업체를 쓰게 되면 처리방침에 국외 이전 항목을 먼저 넣는다, 2026-10-03 MASTER 결정). Resend 키는 2026-10-03 등록(`RESEND_MAIL_API`). 보내는 도메인 인증(DNS)은 도메인 확정 뒤 대표님 조치
  - 판매자 명의 세금계산서·현금영수증은 판매자별 발급자 등록·인증서가 필요하다. 판매자 설정 화면에서 받는다.
