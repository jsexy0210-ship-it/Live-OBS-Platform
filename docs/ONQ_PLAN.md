## 필수 종단 흐름 (검수 9단계에서 증거와 함께 채운다)

| # | 흐름 | 상태 |
|---|---|---|

| E1-B | 결제 엔진 플랜별 확인: 오버레이 전용 7일 체험 → 체험 끝 런칭가 69,000원 첫 결제 → 다음 결제, 통합은 체험 없이 179,000원 첫 결제, 업그레이드 차액 즉시·다운그레이드 다음 결제일·해지 기간 끝까지, 런칭 할인 계정당 1회 | 미착수 |
| E2 | 통합 판매자 가입 → 필요 정보 → 스토어·상품·옵션·재고 → 구매자 주문·결제(sandbox) → OBS → 배송·송장 → 취소·환불·적립금 → 마스터 금액·상태 대사 | 미착수 |
| E3 | 배너 → 안내 → 쇼핑몰 주소로 지원 목록 확인(지원 밖이면 결제·작업 없이 직접 설정 안내) → 110,000원 결제(sandbox, 결제 전 고지 동의 기록) → 자동 연결 → 고객 인증 대기·재개 → 작동 검증(테스트 주문 OBS 표시 증거) → 마스터 진행·완료 조회. 실패 확정 경로: 결제사가 카드 승인 취소를 실제로 확정(sandbox 응답 증거)하고 결제가 환불 완료 상태로 대사되는지, 작업은 완료로 표시되지 않는지 확인. 환불 요청 기록만 생긴 상태(기존 `subscription.refund_required`처럼 감사 기록뿐인 경우)는 통과가 아님 | 미착수 |
| E4 | 장애 발생 → 탐지 → 자동 조치 → 복구 → 데이터 대사 → 마스터 기록·알림 | 미착수 |

## 반드시 넣을 부정·보안 시험

- 지원 목록 밖 쇼핑몰 주소로 자동 연결 구매 시도: 결제 기록·작업이 하나도 생기지 않고 무료 직접 설정 안내만 나오는지
- 비로그인으로 판매자·관리자·결제 완료·자동화 실행 주소 접근, 오버레이 계정의 통합 기능, 판매자의 마스터 기능 접근
- 판매자·주문·작업 ID 바꿔치기, 결제 성공 URL 위조, 과거 결제·인증 재사용, 로그아웃·권한 회수 뒤 열린 탭
- 공개 오버레이 토큰 범위·회수·개인정보 최소화
- 판매자 2곳 이상·독립 브라우저/OBS 교차 접근, 버튼 연타·같은 결제/작업 재전송, 웹훅 중복·역순·누락, 같은 재고 동시 주문
- worker 강제 종료·lease 만료 후 이전 worker 재개 경합, 외부 API 429/5xx, DB 장애, 토큰 만료·회수
- 악성 페이지 지시로 비밀 유출·다른 판매자 접근·범위 밖 동작 유도(자동 연결)
- 단계 부하 10 → 50 → 100 동시 작업, 순간 폭주·장시간 부하(시험 숫자이지 지원 용량 보장 아님)
