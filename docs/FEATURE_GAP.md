# ONQ 기능 격차 분석 — 카페24 관리자 기능 대비

> 작성: 2026-10-02 (KST) · MASTER 검수 · 법령은 출시 전 법률 검토로 확정 · 비교 기준: `docs/PRODUCT_SCOPE.md`, `docs/IA.md`, `docs/ARCHITECTURE.md`, `docs/REFERENCE_MANGOTCG.md` (최신 main)
> 조사 방법 한계: 이 환경에서는 `*.cafe24.com` 도메인 직접 열람이 막혀 있었다(프록시 차단). 카페24 기능 목록은 ① 검색 결과에 노출된 카페24 공식 도움말·매뉴얼 요약, ② 공개 npm 패키지 `@gracefullight/mcp-cafe24-admin@0.2.2` 소스에 들어 있는 카페24 Admin API 엔드포인트 전체 목록(약 250개 경로)으로 교차 확인했다. 로그인·비공개 관리자 접근 없음.

## 결론 먼저

1. **가장 큰 구멍은 「배송」이다.** IA·스키마 어디에도 배송지·송장·배송비가 없다. 개봉한 카드를 구매자에게 실물로 보내는 구조라면 MVP 필수다(보관·합배송 포함). → **대표님 판단 필요: 개봉 후 실물 발송 여부와 방식.**
2. **법정 필수 표시·고지가 비어 있다.** 쇼핑몰 하단 사업자정보(통신판매업 신고번호·호스팅 제공자), 쇼핑몰별 이용약관·개인정보처리방침, 청약철회 제한 고지(「개봉 후 취소 불가」 사전 동의), 미성년자 취소권 고지, 구매안전서비스(에스크로) 표시, 확률형 상품 정보 제공이 IA에 없다. 플랫폼 소개 사이트의 약관·처리방침(PF-008/009)만 있다.
3. **TCG 박스 개봉 특성상 필수:** 청약철회 제한(개봉 = 가치 훼손) 동의, 무통장 주문 입금 확인·자동 취소, 환불 시 적립금·현금영수증 동시 처리, 회원 탈퇴·파기와 거래기록 5년 보존의 분리.
4. 카페24의 디자인 편집기·마켓 연동·공급사·다국어·정기배송·앱스토어 같은 범용 기능 대부분은 **불필요**하다. ONQ의 차별점(주문대기·오버레이·HIT)은 카페24에 없다.

## 1. 카페24 관리자 메뉴 영역별 주요 기능

카페24 관리자 상위 메뉴: 상점관리(쇼핑몰 설정), 상품관리, 주문관리, 고객관리, 게시판관리, 디자인관리, 모바일쇼핑몰, 프로모션, 마케팅센터, 마켓통합관리, 통계, 부가서비스(카페24페이먼츠 등), 앱스토어 [S1][S2]. Admin API는 19개 영역(Store, Product, Order, Customer, Boards, Themes, Promotion, Apps, Category, Collection, Supply, Shipping, Salesreport, Personal, Privacy, Mileage, Notification, Translation, Analytics)으로 나뉜다 [S3][S4].

실제 관리자 화면 확인 (2026-10-02 KST, 대표님 브라우저에서 읽기 전용, 값은 기록하지 않음): 위 구성과 같다. 추가로 확인한 점과 남은 확인 사항은 아래와 같다.
- 주문 메뉴가 상태별 화면으로 나뉜다: 입금전 → 배송준비중 → 배송보류 → 배송대기 → 배송중 → 배송완료, 그리고 취소·교환·반품·환불, 자동입금 확인, 현금영수증, 세금계산서. 홈의 「오늘의 할 일」에 상태별 건수가 뜬다.
- 주문 목록은 「주문현황별」(주문 1건 단위)과 「품목주문별」(상품 1건 단위) 두 탭으로 본다. 목록마다 체크박스로 입금확인·주문취소 같은 일괄 처리를 한다.
- 고객 메뉴에는 회원 등급, 가입 인증, 탈퇴, 휴면, 접속 관리, 회원 태그가 있다. 메시지 메뉴에서 알림톡과 문자를 보낸다.
- 주문 상세와 회원 상세 화면은 아직 항목을 확인하지 못했다.

## 판단 필요 (대표님)

1. 개봉한 카드를 **실물로 배송**하는가, 배송 방식(즉시 / 보관 후 합배송)은? → 배송 범위가 MVP 크기를 좌우한다.
2. **미성년자 구매**를 막을지, 고지 후 허용할지 (판매자 선택으로 둘지).
3. 방송 시작 알림을 **광고성 정보**로 보고 수신 동의자에게만 보낼지.
4. 알림·문자·가상계좌 수수료를 **판매자에게 귀속**할지, 요금제에 포함할지.
