# 디자인 ↔ 개발 차이 조사 (2026-10-05 KST)

> 대표님 질문 「전체 개발 페이지가 왜 디자인과 다른지 확인해」에 대한 1차 조사. 디자인 보드(아티팩트 Version 224)와 개발 화면을 같은 폭으로 나란히 찍어 비교했다. 소유: 디자인 전담. 비교 이미지는 `docs/design-gap/`(왼쪽 보드 · 오른쪽 개발).

## 방법과 한계

- 개발 화면: 최신 main(`32ede56`)을 운영 빌드(`next start`)로 폐기용 DB·데모 시드에 띄워 PC 폭(파트너스 1440 · 마스터 1920 · 쇼핑몰 1440)으로 캡처. 테스트 서버(`e842ce2`)에는 접속하지 않았다.
- **같은 조건이 아닌 것(차이로 세지 않았다)**: 보드의 샘플 데이터(건수·이름·금액), 로그인 상태, 방송 중 여부.
- **비교하지 못한 것(미검증)**: 모바일 폭 전부, 방송 대시보드의 「개봉 중」 카드·주문대기 표(방송 중이지만 그 방송에 연결된 주문이 없음). 장바구니·주문서·마이페이지·주문 내역과 방송 중 상태는 아래 「2차 비교」에서 비교했다.
- 보드 규격 숫자(버튼 폭·높이 등)는 `docs/DESIGN_PROMPT.md` PR #433 기준이며 개발 반영 전이라 공통 컴포넌트 차이는 ③에 묶었다.

## 원인 분류

① 보드 없이 개발 · ② 보드가 개발 뒤에 바뀌었는데 개발 배정 안 됨 · ③ 공통 컴포넌트·토큰이 보드와 다름 · ④ 서버 데이터가 없어 생략 · ⑤ 개발 오구현

## 원인별 요약

- ② 보드가 바뀌었는데 개발 배정이 없음(또는 개발이 서버 기능에 맞춰 단순화): 가장 많다. 목록 화면의 요약 띠·표형 검색·일괄 처리·엑셀, 마스터 홈 차트, 쇼핑몰 홈·상세 확장 구성.
- ③ 공통 컴포넌트·토큰: 높이·폭·Select·날짜·썸네일 — PR #433이 반영되면 대부분 해소.
- ④ 서버 데이터 없음: 요약 집계·PG·방송 이력·구매자 집계. API가 정해지기 전에는 보드의 해당 칸을 「후속」으로 표시.
- ⑤ 개발 오구현: 상품 목록 썸네일 44px·행 세로 정렬(규격 위반), 상품 목록 판매 상태 단일 선택(보드는 복수)처럼 보드 규격을 읽고도 어긋난 것은 소수.
- ① 보드 없이 개발: 체험 안내 띠, 「재고 부족」·「임시 저장」 상태, 「주문 더 불러오기」.

## 권고 순서

1. 보드를 개발에 맞추는 것(개발 맞춤)을 기본으로 한다: 서버가 이미 주는 값과 화면 구성이 다른 목록 화면(상품·주문·회원·파트너스·구독)은 보드를 개발에 맞춰 고치고, 서버 지원 전의 칸은 「후속」 표시.
2. 보드가 맞는 것(보드 맞춤)은 규격 문제(③⑤)와 IA 개편 대상(홈·쇼핑몰 홈·상세·설정)뿐이다.
3. 구매자 화면 4개와 방송 중 상태는 데모 구매자 계정·방송 시드를 추가한 뒤 재비교한다(후속 PR).

## 2차 비교 (미검증 항목 재비교, 2026-10-05 KST)

폐기용 로컬 DB(`obs_gap_test`)에 데모 시드의 구매자 계정(데모 구매자 1)으로 로그인하고, 장바구니에 상품을 담은 뒤 주문서까지 진행해 PC 1440폭으로 찍었다. 방송 대시보드는 파트너스 데모 계정으로 「방송 시작」을 눌러 방송 중 상태를 만들었다(운영·테스트 서버 DB는 쓰지 않았다). 시드 스크립트는 바꾸지 않았다. 구매자 비밀번호는 로컬 DB에서만 시드 파트너스 비밀번호와 같게 맞췄다. 비교 이미지 5장은 `docs/design-gap/`(왼쪽 보드 · 오른쪽 개발).
