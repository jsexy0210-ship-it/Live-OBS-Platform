# 관리자 운영 편의성 원칙 (2026-10-05 대표님 지시)

관리자는 구경하러 오는 사람이 아니라 처리하러 오는 사람이다. 마스터·파트너스 관리자를 「조회 → 상세 → 처리」에서 「목록에서 바로 판단하고 처리」로 바꾼다.

## 원칙

1. 목록에서 즉시 처리: 상세를 열지 않아도 안전한 업무는 행 버튼으로 처리한다. 관리 열은 오른쪽 끝, 같은 레벨 버튼은 같은 폭(버튼 폭 규칙). 버튼이 많으면 주요 2~3개 + 더보기(…), 자주 쓰는 행동은 더보기에 숨기지 않는다.
2. 상세 진입 최소화: 조금 더 볼 정보는 오른쪽 사이드 패널(목록 맥락 유지), 정보가 많거나 독립 주소가 필요하면 기존 상세. 상세에서 처리 뒤 목록으로 강제 복귀하지 않고 [이전]·N/M·[다음]으로 다음 건 처리.
3. 처리 뒤 전체 새로고침 금지: 처리한 행만 갱신, 검색·필터·정렬·페이지·스크롤 유지. 중요 작업은 서버 성공 뒤 상태 변경, 안전한 작업만 낙관적 갱신(실패 시 원복).
4. 확인 단계는 위험도에 맞게: 되돌릴 수 있고 영향이 작은 작업은 즉시 처리 + 토스트 [되돌리기]. 위험 작업은 확인 창. 매우 위험(결제·환불·권한·삭제)은 대상 이름·결과 설명·명확한 확인. 정상 반복 업무에 확인 창을 반복하지 않는다.
5. 일괄 처리: 의미 있는 목록에만 체크박스. 선택 시 표 위 고정 줄(「N개 선택 [승인] [반려] [해제]」). 결과는 성공 N건·실패 N건·실패 사유, 한 건 실패로 전체가 실패하지 않는다.
6. 상태는 다음 행동으로: 코드값(PENDING) 대신 「승인 대기」「확인 필요 2」. 배지는 상태 + 행동 필요 여부를 구분하는 데만. 판단에 중요한 사유는 툴팁이 아니라 행 요약 1~2줄.
7. 경과 시간·업무 정렬: 「2시간 전」「승인 대기 3일째」「답변 대기 14시간」. 기본 정렬은 업무 기준(승인·문의·환불은 오래된 순, 배송은 기한 임박 순, 장애는 심각도→발생 시각).
8. 빠른 필터: 자주 쓰는 조건은 1클릭 칩(예: [전체 18] [확인 필요 4] [오늘 6]). 저장된 보기는 P2, 초기엔 최근 조건 복원.
9. 홈은 업무 받은편지함: 「오늘 처리할 일」 숫자는 조건이 걸린 목록으로 바로 가는 링크.
10. 모바일: 카드형, 주요 액션 2개 + 더보기, 터치 영역 44px.
11. 패널 구조: 외곽 테두리·12px 유지, 목록=[List Header 제목·건수·필터·일괄]·[표], 검색=[조건]·[행동](DESIGN_PROMPT 「외곽 컨테이너 프레임 완전성」).

## 가입 신청(MA-013) 기준 화면

- 행: 쇼핑몰 · 사업자 · 신청일(경과) · 확인(「이상 없음」/「확인 필요 N」) · 관리.
- 자동 점검 이상 없음: 목록에서 [승인](확인 창 없음 또는 아주 짧은 확인) [반려](사유 입력 작은 모달) [상세].
- 확인 필요 사유 있음: [검토](사이드 패널 또는 상세, 사유 요약 확인 뒤 명시적 승인) [상세].
- 일괄: 이상 없는 신청만 [선택 승인] 대상, 확인 필요 건은 일괄 승인에서 제외.

## 우선순위

- P1: 가입 신청 목록 즉시 승인·반려 / 목록 상태(필터·스크롤) 보존 / 홈 업무 받은편지함 링크 / 주문·배송 빠른 처리 / 필터 주소 링크
- P2: 일괄 처리 / 사이드 패널 / 저장된 보기 / 전역 검색 결과 강화 / 인라인 수정
- P3: 단축키 / 개인화

## 완료 기준

목록에서 정상 가입 승인·반려 가능, 안전한 신청 일괄 승인, 처리 뒤 스크롤·필터 유지, 위험 작업 확인 유지, 버튼 규격 통일, PC·태블릿·모바일 확인, 대표 업무별 클릭 수 전·후 보고(예: 가입 승인 「목록→상세→승인→목록」 → 「목록→승인」).
