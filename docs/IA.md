- (2026-10-06 대표님 지시 「회원 가입 신청은 스텝으로 화면 단위 나눈다. 파트너스만」) 파트너스 가입 신청(PF-007)은 한 화면 안에서 접고 펴는 방식이 아니라 단계마다 별도 화면(주소)으로 나눈다: 약관 동의 → 대표자 본인확인 → 정보 입력(필요하면 쇼핑몰·사업자 등으로 더 나눔) → 신청 완료·승인 대기. 각 화면에 진행 단계 표시, 「이전 단계」는 입력값을 유지한 채 돌아가고, 새로고침·뒤로 가기에도 입력값이 남는다(서버 임시 저장 또는 세션 보관, 비밀값 제외). 앞 단계를 건너뛰고 주소로 바로 들어오면 첫 미완료 단계로 보낸다. 구매자 회원가입(SH-011)은 지금 방식을 유지한다.

## AU 공통 인증

```text
AU-001 마스터 관리자 로그인 (이메일·비밀번호, 2단계 인증·로그인 실패 잠금·지정 IP 제한 없음 — 대표님 결정 2026-10-02)
AU-002 판매자 로그인 (화면 이름 「파트너스 관리자」. 상단 탭 「대표자」「직원」으로 나눈다 — 대표님 결정 2026-10-03. 대표자 탭: 이메일·비밀번호 + 아래 한 줄에 왼쪽 「아직 회원이 아니신가요? 회원가입」(「회원가입」만 링크·강조색), 오른쪽 끝 「아이디/비밀번호 찾기」 링크. 직원 탭: 이메일·비밀번호 + 오른쪽 끝 「아이디/비밀번호 찾기」 링크 하나(회원가입 링크 없음 — 대표님 지시 2026-10-04 2차. 「아이디/비밀번호 찾기」는 AU-003·AU-011로 들어가는 진입을 하나로 묶고 화면 위쪽에서 「아이디 찾기 | 비밀번호 찾기」로 바꾼다 — 대표님 지시 2026-10-04. 직원 계정은 대표자가 SA-100에서 만든다). 고른 탭과 계정 종류가 다르면 로그인하지 않고 맞는 탭으로 안내한다. 기본 탭은 대표자. ONQ 로고는 로그인 카드 안 맨 위에 가운데 정렬로 둔다(카드 밖에 따로 두지 않는다))
AU-003 비밀번호 찾기 (판매자: 대표자 휴대폰 본인확인 → 대표자 확인되면 AU-004 새 비밀번호 입력. 메일 링크 없음. 직원: 직원 탭에서 직원 본인 휴대폰 본인확인 → 결과 CI가 그 직원 계정에 연결된 CI와 같으면 AU-004(CI는 직원이 첫 로그인 뒤 본인확인으로 연결, 대표자가 등록한 이름·번호와 맞을 때만). 맞지 않거나 CI가 연결되지 않았으면 「대표자에게 물어보세요」 안내, 대표자는 SA-100에서도 재설정할 수 있다 — 대표님 결정 2026-10-03) → AU-004 비밀번호 재설정
AU-011 아이디 찾기 (판매자: 로그인 아이디는 이메일이다. 대표자 휴대폰 본인확인 → 완료 화면에 가입한 로그인 이메일을 보여 준다. 메일 발송 없음. 직원: 직원 탭에서 직원 본인 휴대폰 본인확인 → 결과 CI가 그 직원 계정에 연결된 CI와 같으면 로그인 이메일을 보여 준다. 맞지 않거나 CI가 연결되지 않았으면 「대표자에게 물어보세요」 안내(대표자는 SA-100에서 직원 이메일 확인). 로그인 화면 대표자·직원 탭 모두 오른쪽 끝 「아이디/비밀번호 찾기」 링크 하나로 들어오고, 화면 위쪽 「아이디 찾기 | 비밀번호 찾기」 전환으로 AU-011·AU-003을 오간다(회원가입은 대표자 탭 왼쪽 「아직 회원이 아니신가요? 회원가입」만 — 대표님 지시 2026-10-04). 한 사람이 여러 쇼핑몰에 계정이 있으면 본인확인 뒤 맞는 계정을 쇼핑몰 이름과 함께 모두 보여 주고, 비밀번호 찾기는 쇼핑몰을 하나 골라 그 계정만 재설정한다. 같은 쇼핑몰 안에서도 맞는 계정이 둘 이상이면 로그인 이메일과 함께 보여 주고 하나를 고른다 — 대표님 결정 2026-10-03)
AU-012 직원 첫 로그인 · 본인확인으로 계정 연결 (대표자가 등록한 이름·휴대폰과 본인확인 결과가 맞으면 CI 연결, 다르면 대표자에게 수정 요청. 건너뛸 수 있고 건너뛰어도 로그인·권한은 그대로이며, 연결 전에는 아이디·비밀번호 스스로 찾기만 막혀 대표자에게 요청 — 2026-10-04)
AU-005 판매자 승인 대기 안내 / AU-006 이용 정지 안내
AU-007 세션 만료 / AU-008 권한 없음(403) / AU-009 페이지 없음(404) / AU-010 점검 중
```

## 2026-10-05 IA 개편 결정 (대표님 지시)

기준: 기능 수가 아니라 「찾는 시간 → 판단하는 시간 → 처리 클릭 수」를 줄인다. 비교 기준은 카페24·스마트스토어센터·쿠팡 WING(관리자), 무신사·29CM·올리브영·컬리(쇼핑몰). 이 절이 아래 기존 절과 다르면 이 절이 우선한다.

### 마스터 관리자
- 홈 맨 위에 「오늘 처리할 일」 업무 묶음: 가입 승인 대기·결제 실패·환불 요청·파트너스 문의·PG 연결 오류·자동 연결 실패·심각 장애·인프라 기준 초과·외부 연결 만료 임박(최고관리자만). 숫자를 누르면 그 조건이 걸린 목록으로 바로 간다.
- 상단 전역 검색: 파트너스·주문번호·결제번호·문의·작업 ID.
- 알림 센터(MA-002)는 알림마다 처리 화면으로 바로 가는 링크를 단다.
- 후속: 저장한 검색 조건, 일괄 작업 통일, 문의 담당자·우선순위·처리 기한, 내보내기 모음, 변경 전후 비교.

### 파트너스 관리자
- GNB 10개 → 8개: 홈 / 방송 / 주문 / 상품 / 고객 / 스토어 / 분석 / 설정.
  - 고객 = 회원 목록·회원 등급·구매 제한·적립금·적립금 원장·회원 알림 + 문의·리뷰(기존 「회원」+「게시판」).
  - 스토어 = 쿠폰(프로모션) + 홈 배너·이벤트 팝업(디자인) + 공지·FAQ.
  - 분석 = 기존 「통계」.
- 홈 순서: ① 오늘 처리할 일(입금 확인·배송 준비·문의 답변·재고 부족·반품 요청, 누르면 조건 걸린 목록) ② 성과(오늘 매출·주문·객단가·취소/환불) ③ 방송(최근·예정·진행).
- 상단 전역 검색(상품·주문번호·회원·문의). 알림 → 처리 화면 바로 가기.
- 상품 목록 빠른 처리: 판매 상태·노출·재고만 목록에서 바로 변경(전체 칸 편집은 하지 않음).
- 후속: 최근 사용 메뉴·즐겨찾기, 저장한 검색 조건, 열 설정, 화면별 도움말.
- 매출·결제(정산 정보): 결제액·취소/환불액·결제수단별 매출·플랫폼 정산 내역. 정산 방식은 「판단 필요」(결제 구조가 플랫폼 결제대행사 키 하나이므로 플랫폼이 파트너스에 정산하는 구조가 된다).
- 분석 추가: 전환 단계(상품 상세 → 장바구니 → 주문 → 결제), 재구매율·신규/기존, 취소·환불률, 시간대별 주문, 방송별 주문·매출·객단가, 재고 소진 속도, 찜 → 구매, 쿠폰 사용 성과. 방송 → 주문 전환을 강점으로 둔다.

### 구매자 쇼핑몰
- 모바일 하단 탭은 홈 / 카테고리 / 검색 / 장바구니 / 내 정보 유지.
- LIVE 전면 배치: 방송 중이면 홈·상단에 「지금 라이브 방송 중이에요 [방송 보기]」, 상품 상세에 「이 상품이 지금 방송 중이에요」.
- 상품 카드: 배지(LIVE·BEST·품절) · 상품명 · 정가·할인율·판매가 · 예상 적립 · 평점·리뷰 수 · 찜·장바구니. 가격 → 혜택 → 신뢰 → 행동 순.
- 검색: 최근 검색어·인기 검색어·자동완성·카테고리 추천·결과 필터·정렬·결과 없음 안내·유사어. 상품명 외 검색 키워드(태그) 지원.
- 상품 상세: 이미지 여러 장 · 평점·리뷰 · 판매가·할인·쿠폰 받기·예상 적립 · 배송비/무료배송 조건 · 재고 · 옵션 · 찜·장바구니·구매하기(모바일 하단 고정) · 상품 정보 · 배송/교환/환불 · 리뷰 요약(평점 분포·사진 리뷰) · 상품 문의 · 추천 상품 · 최근 본 상품 · 공유.
- 추천 상품: AI 없이 같은 카테고리 인기·판매량·최신·운영자 지정으로 시작.
- 장바구니: 전체/개별 선택, 품절·재고 부족·담은 뒤 가격 변경 표시, 옵션 변경, 상품 금액·배송비·할인·예상 적립·최종 금액.
- 주문서: 배송지 → 상품 → 쿠폰 → 적립금 → 배송비 → 결제수단 → 최종 금액 → 약관 → 결제 버튼(모바일 하단 고정). 쿠폰을 상품 → 장바구니 → 주문서까지 연결한다.
- 리뷰: 목록에 평점·리뷰 수, 상세에 평점 분포·사진 리뷰 수·사진만 보기·옵션별·최신/도움순.
- 마이페이지 그룹: 쇼핑(주문 내역·배송지) / 혜택(적립금·쿠폰) / 활동(찜·최근 본·리뷰·문의) / 내 정보(회원정보·알림). 모바일은 전체 메뉴를 본문 위에 펼치지 않는다.

## 2026-10-05 GNB·위계 현대화 (대표님 지시, 위 절보다 우선)

## 모든 화면 공통 상태

기본 · 빈 상태 · 로딩 · 오류 · 권한 없음. 목록 화면은 검색 결과 없음 · 페이지 이동 포함.

## Back · 상태 보존 규칙 (대표님 지시 2026-10-05, 감사 결과 `docs/UX_AUDIT.md`)

기본: 이전 맥락이 있으면 그 맥락으로 돌아가고, 직접 URL로 들어왔으면 부모 화면으로 fallback하며, 검색·정렬·스크롤을 보존한다.

1. 화면 ← 버튼·「목록」·「취소」는 부모 주소로 무조건 push하지 않는다. 앱 안 이전 기록이 있으면 `router.back()`, 없거나 외부·직접 진입이면 부모 경로로 `router.replace`. 로그인 화면이나 다른 계정·다른 쇼핑몰 맥락으로는 돌아가지 않는다. 페이지마다 따로 만들지 않고 공통 Navigation 도우미를 쓴다.
2. 화면 ← 버튼과 브라우저 Back은 다를 이유가 없으면 결과가 같다. 모달 닫기와 페이지 이동은 구분한다.
3. 목록의 검색어·필터·정렬·페이지 크기·탭은 URL 쿼리가 기준이다(예: `/seller/products?q=포켓몬&status=ON_SALE&sort=newest&limit=50`). 개인정보·서버 계약에 맞지 않는 값은 URL에 넣지 않고 history state를 쓴다. 상세 → Back에서 조건과 스크롤을 복원한다.
4. 주소와 연결된 Overlay(Drawer·바텀시트·라우트 모달)는 Back으로 닫는다. 겹치면 위에서부터 하나씩 닫는다. 단순 모달은 Esc·X·취소로 닫고, popstate를 전역으로 가로채지 않는다.
5. 로그인 성공 뒤에는 `replace`로 이동해 Back으로 로그인 화면에 오지 않는다. 로그인된 상태로 로그인 화면에 오면 갈 곳으로 보낸다. 인증은 서버 세션이 판단하며 화면 기록으로 대신하지 않는다.
6. 로그인 뒤 갈 곳(`next`)은 그 영역의 앱 안 경로만 받는다(파트너스 `/seller…`, 마스터 `/admin…`, 구매자 같은 쇼핑몰 `/shop/{slug}…`). 쿼리는 유지하고, 외부 주소·`//`·`\`·`..`는 버린다. 갈 곳이 없으면 그 계정이 열 수 있는 첫 화면으로 보낸다(권한·요금제 모두 반영).
7. 저장하지 않은 변경이 있는 큰 폼(상품 등록·수정, 설정, 오버레이 편집)은 화면 ←·브라우저 Back·GNB·LNB·경로 줄·다른 링크·새로고침·탭 닫기에 같은 확인을 띄운다. 일부 경로만 막지 않는다.
8. 권한 없음·요금제 제한·없는 대상·오류 화면에는 다음 행동(목록으로·이전 화면·구독·결제·다시 시도·홈) 중 최소 하나를 둔다.

9. (2026-10-05 대표님 지시) 최상위 메뉴 화면을 뺀 모든 화면은 진입 즉시 화면 ← 버튼이 보인다. 화면마다 「들어오는 길 → 돌아가는 곳」을 전부 계산해 `docs/BACK_ROUTES.md` 경로표로 관리하고, 구현은 이 표를 따른다. 새 화면을 만들면 경로표에 같은 PR로 추가한다.

공통 Navigation 도우미 사용법: `lib/client/navigation/` — `useSmartBack(parent)`(1항), `useUrlState(defaults)`·`useScrollRestore(key, ready)`(3항), `useUnsavedGuard(dirty)`·`confirmLeave`(7항), `sanitizeNext(raw, NEXT_SCOPE.*)`(6항). 앱 안 이동 기록은 루트 레이아웃의 `<NavigationTracker />`가 쌓으며, 없으면 화면 ←는 항상 부모로 replace한다.
